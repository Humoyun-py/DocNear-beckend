# DocNear secret handling

Keep populated environment files and signing material outside the repository.
The repository may contain only `.env.example` templates. `.gitignore` covers
`.env`, `.env.*` (while allowing examples), `local.properties`, keystores,
build outputs and runtime QA files.

Secrets include Django `SECRET_KEY`, database credentials, SMS API keys,
Telegram bot token/secret, JWTs, OTP values, SMTP credentials, Maps keys and
release-keystore passwords. Never expose them through `VITE_*`, Dart source,
Android resources, logs, screenshots or committed Postman environments.

Django can load an external local file through `DOCNEAR_ENV_FILE`. Production
should inject values from its secret manager. Restrict local files to mode 600
and their parent directory to mode 700.

OTP codes are generated by Django with a cryptographic generator and stored only
as password hashes. SMS and Telegram adapters may receive the plain value only
for immediate delivery and must not log it. Deterministic `111111` exists only
in `config.settings.test`. Rotate any token or key that has ever entered Git,
chat, screenshots or shared logs.

The maintained Telegram worker is
`DocNear-web-frontend-main(2)/DocNear-web-frontend-main/telegram_bot.py`. It
requires `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_SECRET` and
`DOCNEAR_API_BASE_URL`; it does not generate or persist OTP codes.
